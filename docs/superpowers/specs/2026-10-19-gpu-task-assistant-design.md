# GPU 任务助手与任务详情改版

状态：用户已确认并要求执行；正在实现，尚未发布。

## 目标与依据

用户需要一个理解当前集群、能继续查询任务并设置提醒的 GPU 任务助手。现有聊天缺少默认上下文、只接收快照、没有工具、只显示纯文本；展开详情仍是截断命令的窄表格。本方案替代旧方案中“可选快照总结器”的定位。

保留现有仪表盘主界面、OpenAI / Anthropic 协议、自定义地址和模型、SecretStorage 密钥、服务器分区和 GPU 矩阵。聊天是带侧栏的小窗口，不能替换仪表盘或占用整个标签页。整体保持克制，颜色用于空闲、运行、异常、离线状态，图标沿用现有线性图标。SSH 必须从用户本机发起。遵守禁止 Computer Use 的要求。

## 方案选择

- **采用：复用现有 Webview、HTTP 客户端和 SSH 采集，加入原生工具调用、带侧栏的聊天小窗口和持久提醒。** 能完成连续追问、实际查询和提醒，不引入 Agent 框架。
- 只改聊天样式与提示词：能改善可读性，但无法回答父进程或真正设置提醒，不能满足需求。
- 无限制终端 Agent：难以保证不会误操作；采用可组合的科研查询工具，覆盖任务、日志、调度、资源诊断和提醒。

## 1. 聊天界面

主界面仍是现有仪表盘。点击 AI 打开浮在仪表盘上的聊天小窗口，沿用现有对话框基础。窗口宽度不超过 880px 或视口宽度减 32px，高度不超过 720px 或视口高度减 48px；顶部保留会话标题、清空、设置和关闭。删除推荐问题和两项上下文勾选。

┌───────────────────────────────────────────────────┐
│                 GPU 任务助手            设置  关闭 │
│                                                   │

│  用户问题                                当前范围  │

│  Markdown 回答                           GPU 概况  │

右侧栏约 200px，主聊天占剩余空间；视口窄于 680px 时侧栏折叠为可展开区域。侧栏只放当前服务器/GPU/任务、数据时间、查询记录和提醒；不引入多会话管理系统。关闭窗口保留仪表盘筛选、选择和滚动；重新打开聊天保留本次会话。会话正文默认不写入磁盘。窗口开关遵守键盘焦点和 Escape 行为，关闭后恢复到打开按钮。

Markdown 支持段落、标题、列表、表格、引用、行内代码、代码块。代码块可复制，长表格在自身区域滚动。使用成熟解析器，禁用原始 HTML、远程图片和危险链接；外部链接只允许 HTTP(S)，点击后通过 VS Code 打开。禁止直接注入模型返回的 HTML。

响应逐步显示，生成时可停止。输入支持中文输入法，Enter 发送、Shift+Enter 换行；正在输入候选词时不发送。用户向上阅读时不强制滚动到底部；查询错误保留问题并提供重试。重试不重复创建提醒。

## 2. 默认具备上下文的 GPU 助手

每轮手动发送时自动附带当前监控范围的简要状态、采集时间、选中的服务器/GPU以及有关工具结果。侧栏可查看本轮使用的数据与接口域名，明确这些数据会发送到用户配置的服务。打开页面、自动刷新和后台提醒均不调用 AI。

默认摘要包含服务器显示名、GPU 型号/索引、显存、利用率、空闲判定和进程概况；完整命令、调度详情和任务日志按需取得。实际 SSH 地址在本地映射为工具标识，不靠模型返回任意主机字符串。命令和日志中的常见密钥参数需要遮盖；不得读取环境变量、密钥文件或任意任务文件。日志来源与读取范围必须可见，详见下文。

助手可以讨论 GPU 选卡、显存需求、训练/推理、CUDA、任务排查与资源安排。区分实际观测、推断和一般建议；不凭环境名认定训练任务，不把剩余显存等同于空闲，不根据一次快照预测结束时间。聚焦用户的 GPU 工作，不采用通用聊天自我介绍。工具由模型按问题组合调用，不按固定关键词匹配预设答案。

“现在呢”“有哪些卡可用”需要新鲜数据；过期、离线或重复服务器不能作为可用资源。连续追问沿用此前确定的服务器和 GPU；存在多个候选时才询问具体对象。

## 3. 真实工具调用与执行边界

### 本机 SSH

现有 `extensionKind: ["ui", "workspace"]` 允许远程扩展宿主回退，不能保证总从本机连接。调整为桌面本机 UI 扩展，SSH 子进程和 SSH 配置读取都在本机执行，即使当前窗口打开的是 Remote SSH 或容器工作区。侧栏标明连接由本机发起；仅远程安装的用户需要在本机安装，浏览器版 VS Code 不提供本机 SSH。

使用本机 `ssh`，继承用户明确选择的 SSH 配置（默认 `~/.ssh/config`）、密钥代理、端口及 ProxyJump。不复制私钥，不让 API 服务连接主机，不从当前远程工作区再跳去目标主机。局域网/VPN/公网可达性由本机网络与 SSH 配置决定，连接失败显示认证、主机密钥、超时等可操作原因；不关闭主机密钥校验、不请求 sudo、不由模型覆盖 SSH 配置或添加 ProxyCommand。用户现有 SSH 配置属于用户信任边界。

### 可组合的科研查询

使用 OpenAI Chat Completions / Anthropic Messages 的结构化工具调用。模型选择工具，扩展验证并执行，再把结果交给模型继续回答；不从自由文本或 Markdown 中提取命令执行。

以下工具提供实际 SSH 证据，模型可根据问题组合使用：

| 操作 | 执行内容 |
| --- | --- |
| 获取/刷新 GPU 状态 | 复用已有 SSH 查询、并发限制和刷新合并 |
| 查询任务来源 | GPU 进程、最多 8 层父进程、相关子进程、启动时间、工作目录、同一任务占用的 GPU |
| 查询调度任务 | Slurm 作业/步骤、排队原因、时间上限、工作目录、标准输出/错误路径；结束后按作业 ID 查询 accounting 状态和退出原因 |
| 发现任务日志 | 只解析相关进程 stdout/stderr 的目标与 Slurm 日志路径，不读取管道或设备，不遍历整个磁盘 |
| 读取已授权任务文本 | 对明确的日志/进度文件读取有限末尾内容和文件修改时间，提取进度、速度、异常、最近 checkpoint 记录 |
| 查询资源与瓶颈证据 | 短时 GPU 利用率采样、相关进程状态、CPU/RAM、相关文件系统空间、GPU 拓扑及驱动信息 |
| 新建/列出/取消提醒 | 修改本地提醒记录并返回实际保存结果 |

进程查询使用固定只读命令，限定已配置服务器与当前 GPU 关联任务；通过已发现的父进程/作业关系继续追查，不允许任意扫描其他用户的所有进程。记录 PID 与启动身份，避免 PID 复用造成误判。进程消失、权限不足、容器 PID 命名空间、父进程不可见分别报告，不尝试提权或进入容器。查询按需执行，不在每次仪表盘刷新中遍历进程树。

Slurm 查询必须限定只读子命令，例如 `scontrol show job`、`squeue`、`sacct` 的选定查询参数；不能只按 `scontrol` 可执行文件名放行。无 Slurm 的普通 SSH 服务器同样支持进程、日志和资源查询，不能强制依赖调度器。

日志按具体文件授权：尚未授权的路径在对话中显示服务器、文件、读取范围及接收 API，提供允许本次、始终允许此文件、拒绝；待执行查询直接等待用户决定并自动继续。侧栏保留已保存许可的撤销及手动添加路径。授权限制为该服务器上的规范化路径，保存路径许可而不保存日志内容；取消授权后停止读取。拒绝非普通文件、越界符号链接、`/proc/*/environ`、SSH/云服务凭据等敏感路径；默认读取末尾 500 行且不超过 256KiB，可在设置中分别调整至 10,000 行及 2MiB。不执行文件，不将路径作为 shell 代码，不用 `tail -f` 或无限制 `find`。用户日志可能包含私人实验信息，读取与发送到所配 API 的行为必须在界面中明确。

不暴露任意 shell、kill、sudo、提交任务、改训练参数、删除文件、安装软件或任意远端写操作。模型输出的启动/修复建议命令可复制或放入终端供用户审阅，不自动运行。服务器、日志和进程字段属于不可信数据，不能改变工具权限。工具调用默认无固定次数限制，设置值 0 表示不限，可选正数预算达到后暂停并保留待执行操作。单次 SSH 复用现有 2–60 秒超时，资源短时采样最多 5 秒；单个工具结果超过 1MiB 时保留有标记的摘录。较早的完整工具组压缩为有界的事实摘录，保留协议配对及近期证据；界面保留最近 80 条已结束过程记录、单条详情约 16k 字符。取消后不再启动后续操作，继续时重试被中断的操作；已成功保存的提醒不会重放或因停止回答被撤销。AI 单次请求默认超时 120 秒，可设置至 900 秒；失败保留可用错误码和实际请求阶段。

调用过程以简短步骤展示，例如“查询 GPU 6、7 → 追溯父进程 → 找到训练入口”。不会只说“需要我帮你查吗”却无法查询。若模型/服务不支持工具调用，明确提示兼容性问题，保留普通 GPU 问答，不假装查询或执行成功。

### 面向科研场景的完整工作流

| 用户问题 | 助手应继续取得的证据与回答 |
| --- | --- |
| “6、7 卡具体跑什么，是同一个实验吗？” | 从 worker 追到 launcher/脚本，结合共同父进程、Slurm 作业、GPU UUID 和已授权日志识别；给出入口、用户、运行时长和证据，环境名只作线索 |
| “训练到哪了，大概什么时候结束？” | 查总 steps/epochs、当前进度和速度；有足够证据时计算估计，否则说明缺少总量或速度并引导关联日志 |
| “显存满了但 GPU 不动，是不是卡住了？” | 短时利用率、CPU/进程状态、日志最后更新时间和末尾异常；区分可能的数据加载、同步、保存 checkpoint、进程阻塞，不能仅凭低利用率断言死锁 |
| “任务突然没了，是正常结束还是炸了？” | 查原任务身份、Slurm/accounting 状态及已授权日志；有证据时报告 OOM、超时、异常退出或正常完成，无记录就不能声称成功 |
| “我要两张 32G 卡，放哪比较合适？” | 根据同机可用 GPU 数、显存、型号和需要时的互联拓扑提出候选；说明现有占用和快照时间，不把跨服务器的卡当单机多卡 |
| “为什么排队，还要等多久？” | 解释调度器排队原因；有调度器提供的预计启动时间则引用并注明可变，没有则明确无法保证，不能用其他任务的超时时间编造准确等待时长 |
| “日志提示 OOM/NCCL/磁盘写失败，帮我看看” | 结合相关日志、进程显存、驱动/拓扑及相关文件系统容量定位证据；给出可审阅的处理建议，不擅自降 batch、重启或清理数据 |
| “帮我盯着，结束/空闲后通知我” | 建立与 GPU 或任务身份绑定的本地提醒，显示条件与截止时间，不要求 AI 会话保持打开 |

这些工作流使用同一组工具，不为每个框架写一个适配器。优先识别常见 steps/epochs、`x/y`、it/s 或 s/it 进度；不认识的格式仍可基于原文解释，不伪造结构化进度。

### 结束时间的证据规则

- 已结束作业：显示实际结束状态/时间与来源；普通进程消失只能说明“不再运行”，不能推断退出码。
- 有日志总进度和速度，或至少两个同一阶段的带时间戳进度点：按剩余工作量与观察速度估计，显示计算依据和采样时间；这是当前阶段的估计，验证、checkpoint、排队及后续阶段未覆盖时明确说明。
- Slurm 运行中的 `EndTime` / `TimeLimit`：作为调度时间边界单独显示，不当作模型已算出的训练完成时间；结束后的实际时间另行处理。
- 只有 `nvidia-smi` 或运行时长：可以描述状态，不能可靠估算还剩多久。能够建立结束/释放提醒，不虚构倒计时。

## 4. GPU 释放、任务结束与定时提醒

将“提示时间”按两种明确意图处理：

- **释放提醒**：指定服务器/GPU，检测实际空闲后通知；可指定生效时间与截止时间。未给截止时间时默认有效 24 小时，并在回执中显示。
- **任务结束提醒**：绑定 Slurm 作业或进程及其启动身份，观察到结束后通知；能够查到退出原因则附上，无法区分成功/失败则如实提示。未给截止时间时同样默认有效 24 小时。不能监听到任意一个 worker 退出就认定整个任务完成。
- **定时检查提醒**：例如“20 分钟后提醒我看一下这张卡”，到时查询并通知当前状态，不承诺它届时一定释放。

多个 GPU 默认全部满足才通知；用户说“任意一张”时任意满足即可。空闲判定复用插件设置，释放需连续两次新鲜成功采样满足，避免瞬时波动。首次采样已经空闲时如实说明，不称为“刚释放”。离线、陈旧缓存、重复主机和查询失败均不能触发释放。

提醒保存到本地 VS Code 状态，侧栏可查看、取消。AI 新建或取消后展示服务器、GPU、条件、绝对时间和执行回执，支持撤销新建；不需要 AI 一直在线。相同请求重试不能产生重复提醒。

提醒调度由本机扩展持有，不依附聊天或仪表盘。有效释放/任务结束提醒每 30 秒检查相关服务器，复用近期查询并合并同主机请求；只有定时提醒时只安排到时检查，无相关提醒时不额外轮询。后台只执行确定的查询与判定，不读取新日志或调用 AI。关闭仪表盘仍有效，VS Code 退出或机器休眠期间不运行；恢复后重新取样，已过期的条件提醒标记过期，错过的定时提醒只补报一次并标明延迟。

显式创建的提醒与原有全局异常通知独立，避免受默认关闭的通知开关影响；同一事件不重复弹窗。提醒只能通知，不能预留 GPU 或保证通知后资源仍可用。

## 5. 展开的 GPU 任务详情

保留 GPU 矩阵，下方展开区重新组织为“摘要 → 任务列表 → 选中任务详情”。

- 摘要：服务器/GPU、型号、利用率、显存、采集时间及异常原因。
- 任务列表：用户、可识别的任务入口、运行时间、显存、PID；按用户/任务关系展示，多进程仅在已验证共同父进程或 Slurm 作业时归组。
- 选中任务：可换行的完整命令、父子关系、Slurm 作业信息、已授权日志关联与进度证据、复制操作。未查询时显示“查询任务来源”，避免把 Python worker 当成已识别的训练脚本。深度查询结果带采集时间，普通 GPU 刷新不无声覆盖为新的“实时结论”。
- 主要操作：“问 AI”“释放时提醒我”；问 AI 自动带入所选 GPU/任务。复制 PID、命令与准备终端操作保留，终端命令仍由用户执行。

刷新保持选中项、焦点和滚动，不自动折叠或跳到其他 GPU。选中进程退出时保留其详情并显示“已结束/不再出现在本次采样”，不让选择跳到复用该 PID 的新进程。窄窗口不靠挤压七列表格呈现信息。

## 6. 用户追加的显示范围与设置改进

用户要求能在设置中选择每台服务器的指定 GPU，并主动检查遗漏的设置和不合理交互。

- `visibleGpus` 按 SSH 别名保存 GPU 索引或 UUID；未指定服务器表示全部卡（含新增卡），空数组表示不显示卡。设置页提供服务器分区和卡勾选，保留完整 GPU 目录，避免隐藏后无法选回。
- 仪表盘、统计、可用 GPU 选择器与默认 AI 上下文使用相同范围；后台提醒继续监测已绑定的卡，并显示范围外目标。
- 补齐监控/排除主机和通知事件设置；关闭自动刷新或 Slurm 后禁用对应的依赖项，不影响已建立的提醒。
- 当前页重置只改变待保存草稿；关闭未保存设置需要明确保存或放弃。聊天进入 AI 设置后，关闭设置回到原会话。

## 7. 修改范围与迁移

- `aiClient.ts`：协议工具消息、流式响应、取消及请求限制；保留端点和 SecretStorage 标识兼容。
- `aiController.ts`：自动上下文、工具循环、逐步结果；删除预览令牌与旧勾选流程。
- `assistantView.ts`：带侧栏的聊天小窗口、Markdown、日志授权和工具过程展示；中英文文案同步。
- `gpuMonitor.ts`：复用现有 SSH 执行和采集。新增一个聚焦任务调查的模块，生成固定查询命令并解析父进程、调度、日志与资源证据，不把这些全部塞进视图文件。
- `gpuView.ts` / `extension.ts`：小窗口与仪表盘选择联动、共享查询与扩展级提醒生命周期；避免页面和提醒重复发起相同查询。
- `package.json`：本机 UI 扩展声明；保留用户已有 API 和 SSH 配置。
- `webviewTemplate.ts`：任务展开区、关联 AI 入口和保持交互状态。
- 一个直接的本地提醒模块；现有配置声明和设置页只增加用户实际需要的入口，不引入通用工作流或 Agent 框架。

## 8. 必须验证的实际行为

只补会保护本次行为的检查，使用合成服务器与进程，不保存用户真实聊天、路径、命令或密钥：

1. 本地 HTTP 服务覆盖两种协议的真实工具往返、连续追问、流式拆包、取消和不支持工具的错误；不是硬编码答案匹配。
2. SSH 调用参数与进程解析覆盖本机执行声明、父进程链、PID 复用、消失/无权读取、恶意主机/PID/路径输入、日志授权与截断、调度器只读子命令；验证没有任意命令执行入口。
3. 进度检查覆盖 steps/epochs/速度、证据不足、阶段变化；调度时间上限不能冒充训练 ETA。提醒以可控时间和采样检查稳定空闲、任务结束、定时、生效/过期、重试去重、恢复和一次通知。
4. 现有 DOM 检查覆盖 Markdown 注入与危险链接、主仪表盘保留、聊天小窗口侧栏、移除勾选/推荐、会话保留、任务选择和刷新焦点；不宣称 DOM 检查等于真实视觉验收。
5. 编译、lint 和受影响的现有检查；不添加无关回归项目，不使用 Computer Use，不读取用户 SecretStorage 发起真实服务请求。

## 验收示例

连续问“有哪些卡可用 → V100 的 5、6、7 在跑什么 → 6、7 具体是什么任务”，助手能够从本机 SSH 刷新、解析对象、查询共同父进程并引用结果；接着问“到哪了，还要多久”，能发现日志来源，经用户选定文件后读进度，给出有依据的当前阶段 ETA；若无日志/权限则说明缺少的证据。随后说“这两张卡释放后提醒我，今晚十点前有效”，会创建可见、可取消、实际运行的提醒。整个过程都在仪表盘上的聊天小窗口内完成。

## 已知限制

模型推理能力和工具协议支持取决于所选服务；工具只保证本地权限边界，不保证模型每句话正确。父进程、容器映射、日志或 accounting 可能不可访问；训练结束时间受日志质量与阶段变化限制。常见敏感参数遮盖不是完整数据脱敏，用户应仅授权允许发送给其 API 的任务文本。持续提醒依赖本机 VS Code 扩展宿主运行，轮询与网络会带来延迟。仅远端安装需要迁移到本机；浏览器版不支持。禁止 Computer Use，因此本轮不能声称经过真实窗口视觉验收。
